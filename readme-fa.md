### چرا این پروژه؟ ارتباط نفت و ساختمان از طریق JUIA
این سامانه بازخوانی مدرن یک پروژه دانشگاهی معماری است که با رویکرد **Cost Control + Applied AI** توسعه یافته است. همان‌طور که در پلتفرم یکپارچه **JUIA** (طراحی شده برای تخمین هزینه، ارزیابی اقتصادی و مدل‌سازی مالی در میادین نفتی) هسته مرکزی «بهینه‌سازی سود و هزینه» بود، اینجا نیز تمرکز بر **مدل‌سازی ریاضی هزینه‌ها** در محیط‌هایی با داده‌های ناقص است.

*   **در JUIA:** محاسبه هزینه‌های حفاری و تولید بر اساس متغیرهای پیچیده عملیاتی، قراردادی و مدل‌سازی مالی.
*   **در این پروژه:** محاسبه هزینه‌های بازسازی بر اساس هندسه نقشه، کیفیت مصالح و زمان‌بندی اجرا.
*   **نقطه اتصال:** انتقال دانش دامنه (Domain Knowledge Transfer) از سیستم‌های Enterprise نفت به چالش‌های مقیاس کوچک‌تر ساختمانی، بدون از دست دادن دقت مهندسی. استفاده از موتورهای ارزیابی هیبریدی (Rule-Based + ML) که در Vessel Tracking برای مناقصات ناوگان استفاده شد، اکنون برای اولویت‌بندی گزینه‌های بازسازی به کار رفته است.

##  معماری فنی و چالش‌های مهندسی

برخلاف اپلیکیشن‌های وب معمولی (CRUD) یا داشبوردهای IoT، این سیستم یک **Engineering Software** محسوب می‌شود که شامل پایپلاین‌های محاسباتی هندسی و موتورهای تخمین هزینه هیبریدی است.

### ۱. پردازش تصویر و استخراج هندسه (Computational Geometry Pipeline)
به جای استفاده از مدل‌های Deep Learning سنگین که نیازمند دیتاست‌های برچسب‌خورده عظیم هستند، از یک **پایپلاین هندسی تحلیلی** استفاده شده است. این انتخاب آگاهانه نشان‌دهنده درک محدودیت‌های واقعی داده در صنعت است:
-   **پیش‌پردازش تطبیقی:** استفاده از `Adaptive Thresholding` و کنترل دستی Brightness/Contrast توسط کاربر (Human-in-the-loop) برای غلبه بر نویز تصاویر اسکن‌شده.
-   **استانداردسازی زوایا:** الگوریتم اختصاصی برای Snap کردن خطوط کج دست‌نویس به زوایای استاندارد معماری (۰، ۵، ۹۰ درجه).
-   **بازسازی توپولوژی:** استفاده از الگوریتم‌های گراف و تقاطع خطوط برای تشخیص اتاق‌های بسته (Room Detection) بدون نیاز به یادگیری عمیق.
-   **چشم‌انداز آینده:** ارتقاء به U-Net/DeepLabV3+ در فاز بعدی برای سگمنتیشن معنایی، مشروط به فراهم شدن دیتاست آموزشی معتبر.

### ۲. موتور برآورد هزینه هیبریدی (Hybrid Cost Engine)
الهام‌گرفته از سیستم‌های ارزیابی مناقصات در پروژه‌های فراساحلی (مانند Vessel Tracking)، این ماژول از دو لایه تشکیل شده است:
-   **لایه قانون‌محور (Rule-Based):** استفاده از تمپلیت‌های مهندسی برای آیتم‌های استاندارد.
-   **لایه پیش‌بینی (ML Prediction):** استفاده از مدل‌های XGBoost چندگانه (Multi-Model Architecture) برای تخمین قیمت آیتم‌های متغیر.
-   **ماژول ارزیابی (Evaluation Module):** منطق وزن‌دهی و امتیازدهی نهایی (Bidding Evaluation) به دلیل محرمانگی داده‌های صنعتی، فعلاً در قالب فایل‌های اکسل پیوست شده است تا اصول مهندسی داده را بدون افشای الگوریتم‌های اختصاصی شرکت‌ها نمایش دهد.

### ۳. تعامل‌پذیری و خروجی استاندارد
-   **خروجی Sweet Home 3D (.sh3d):** تولید فایل XML استاندارد برای امکان ویرایش و مشاهده سه‌بعدی در نرم‌افزارهای موجود.
-   **گزارش‌گیری هوشمند (NL2SQL):** پیاده‌سازی رابط زبان طبیعی برای پرس‌وجو از پایگاه داده هزینه‌ها (با استفاده از LLM محلی و تبدیل ایمن به SQL).

### نصب و راه‌اندازی
1. کلون کردن مخزن:
   ```bash
   git clone https://github.com/yourusername/smart-construction-ai.git
   cd smart-construction-ai
   ```

2. ایجاد محیط مجازی و نصب وابستگی‌ها:
   ```bash
   python -m venv venv
   source venv/bin/activate  # در ویندوز: venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. اجرای سرور:
   ```bash
   uvicorn main:app --reload --port 9000
   ```

4. مراجعه به آدرس `http://localhost:9000` در مرورگر.

## 💡 درس‌آموخته‌های کلیدی (Key Takeaways)

این پروژه بازتاب‌دهنده تجربیات من در توسعه سیستم‌های **Well-Watch**، **Vessel Tracking** و **JUIA** است:
1.  **Pipeline داده، پیش‌شرط هوش مصنوعی است:** موفقیت الگوریتم CV وابسته به پیش‌پردازش صحیح و تعامل کاربر است، نه فقط پیچیدگی مدل.
2.  **دانش دامنه مکمل تخصص الگوریتمی است:** انتخاب ویژگی‌ها و اعتبارسنجی مدل در محیط‌های صنعتی، بیش از انتخاب الگوریتم، به درک عمیق از فرآیندهای عملیاتی وابسته است.
3.  **معماری ماژولار حیاتی است:** جداسازی لایه‌های Core، Service و Repository اجازه می‌دهد الگوریتم‌ها مستقل از فریم‌ورک وب تست و توسعه یابند.
4.  **انتخاب ابزار مناسب:** استفاده از روش‌های کلاسیک CV به جای Deep Learning در اینجا یک انتخاب مهندسی آگاهانه برای کاهش وابستگی به داده‌های آموزشی و افزایش قابلیت تفسیر (Interpretability) بوده است.
